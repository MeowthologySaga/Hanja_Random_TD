# 에이전트 인계 폴더

코덱스와 클로드가 같은 저장소를 보면서 **파일로** 주고받는 곳입니다.
서로 직접 메시지를 보낼 수는 없으므로, 여기에 두고 사용자가 상대에게 한마디만 전달합니다.

## 폴더 역할

| 경로 | 넣는 쪽 | 읽는 쪽 | 내용 |
|---|---|---|---|
| `to-claude/` | 코덱스 | 클로드 | 생성한 인게임 이미지 + `request.md` |
| `to-codex/` | 클로드 | 코덱스 | 적용 결과 + 추가로 필요한 에셋 요청 |
| `LOG.md` | 양쪽 | 양쪽 | 주고받은 내역 한 줄씩 |

이미지 파일 자체는 git에 올리지 않습니다(`.gitignore` 처리). 이 `README.md`와 `LOG.md`만 추적합니다.

## 순서

1. 코덱스가 `to-claude/`에 이미지 저장 + `request.md` 작성 + `LOG.md`에 한 줄 추가
2. 사용자가 클로드에게 "확인해봐"
3. 클로드가 읽고 UI에 반영 → `to-codex/`에 결과·추가 요청 작성 + `LOG.md`에 한 줄 추가
4. 사용자가 코덱스에게 "handoff/to-codex 봐"

## 파일 이름 규칙

`<대상화면>-<컴포넌트>-<버전>.png`

예: `panel-frame-v1.png`, `summon-card-bg-v2.png`, `tab-icons-v1.png`

## `request.md` 양식

이미지만 있으면 어디에 어떻게 쓸지 알 수 없으므로 아래 항목을 채웁니다.

```markdown
## panel-frame-v1.png

- 대상 화면: 우측 조작 패널
- 대상 컴포넌트: .control-panel 바깥 테두리
- 의도한 표시 크기: 400x720 (가변 높이)
- 배경: 투명 PNG
- 9-slice: 필요 / 상하좌우 여백 48px 고정
- 색 계열: 먹색 + 금색 테두리
- 비고: 모서리 문양은 잘리면 안 됨
```

### 특히 중요한 항목

- **9-slice 여부** — 패널·버튼처럼 크기가 변하는 요소는 늘어나도 되는 중앙 영역과 고정 여백을 지정해야 실제로 쓸 수 있습니다. 이게 없으면 프레임 이미지는 사용 불가입니다.
- **배경 투명 여부** — 자홍색(`#ff00ff`) 크로마키가 남아 있으면 알려주세요. 기존 파이프라인처럼 제거 처리하겠습니다.
- **의도한 표시 크기** — 실제 표시 크기보다 작게 생성되면 확대로 흐려집니다. `docs/design/v032-sprite-quality-audit.md`에서 같은 문제가 한 번 있었습니다.

## 참고

- 게임 설계 기준 해상도: 1280x720 (`.game-shell`)
- 전장 캔버스: 880x720, 우측 패널: 400x720
- 오행 5색 체계를 따르는 에셋은 木/火/土/金/水 5종 세트로 주세요.
